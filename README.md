# web-music-player

一个轻量的自托管 MP3 网页播放器。指定 Linux 上的音乐目录，即可在浏览器中听歌；服务端只使用 Python 标准库，前端无需安装依赖或编译。

## 功能

- **流式播放**：按需读取 MP3，支持 HTTP Range 请求和拖动进度。
- **自绘播放器**：细进度条和时间显示，左侧 SVG 上一首、播放/暂停、下一首，右侧切换顺序/随机模式；唱片随实际播放旋转。
- **音量浮窗**：悬停或点击喇叭展开纯滑条，拖到最左端静音；音量与静音状态随刷新保留。手机点击展开，点击外部收起。
- **稳定随机队列**：每轮随机顺序固定且不重复，上一首/下一首沿历史前进后退；刷新和手动点歌不会重洗剩余随机顺序。
- **下一首播放**：在歌曲或搜索结果旁添加待播歌曲，按添加顺序优先播放，也可再次点击取消。
- **状态记忆**：刷新后恢复列表顺序、随机开关、当前歌曲、进度、搜索内容和列表展开状态。
- **搜索与折叠列表**：按文件名搜索；全部歌曲默认收起，搜索不改变播放队列。
- **动态歌词**：读取本地 LRC，当前句高亮并增加 4px，紧邻上下行增加 1px，其余行保持基础字号；自动跟随使用自定义缓动，隐藏滚动条，手动滚动保留原生手感。
- **简单部署**：一个 Python 服务同时提供网页和音频，可直接运行，也可由 systemd 管理。

## 快速开始

需要 **Python 3.8 或更新版本**和支持 HTML5 音频的现代浏览器。运行服务不需要 Node.js、pip 依赖或 Nginx。

在项目根目录执行：

```bash
python3 server.py "/home/you/Music" --port 8080
```

然后访问 `http://服务器IP:8080/`。已有网络转发时，让转发目标指向对应的服务端口即可。

参数：

| 参数 | 作用 | 默认值 |
| --- | --- | --- |
| `folder` | 必填，存放 MP3 的目录 | — |
| `--port` | HTTP 监听端口 | `8080` |
| `--bind` | 监听地址 | `0.0.0.0` |
| `--lyrics-dir` | 单独指定歌词目录 | `<音乐目录>/Lyrics` |

例如，只监听本机并指定独立歌词目录：

```bash
python3 server.py "/home/you/Music" \
  --bind 127.0.0.1 \
  --port 8080 \
  --lyrics-dir "/home/you/Lyrics"
```

服务只扫描音乐目录的当前层，`.mp3` 后缀不区分大小写，支持中文、空格等文件名。新增歌曲后点击“刷新列表”。第一次按文件名排序，后续保留已有歌曲的顺序，将新增歌曲追加到末尾，并移除已删除歌曲。

## 下一首播放

在“全部歌曲”或搜索结果中，点击歌曲旁的“下一首播放”即可加入待播队列，不会打断正在播放的歌曲。按钮变为“取消待播”，再次点击即可取消。

多首待播歌曲按添加顺序播放，优先于顺序或随机模式；手动点“下一首”和歌曲播放结束时都会使用这个队列。队列播放完后恢复原来的播放模式。同一首歌不会重复入队；直接点击某首歌曲立即播放时，它也会从待播队列中移除。

播放器下方会显示待播数量和下一首歌名。队列随播放状态一起保存，刷新后继续保留；已删除的歌曲会自动移出队列，更换音乐根目录时会清空旧队列。

## 播放与随机规则

- 右侧模式按钮在顺序播放、随机播放之间切换；图标表示当前模式，平时不显示圆底，鼠标悬停或按下时才显示反馈。触屏松手后反馈消失。
- 音量浮窗仅显示滑条，支持键盘方向键调整、Escape 收起；滑条左端为静音。网页调音受浏览器支持情况限制，部分移动端由系统控制音量。
- 播放和音量控件使用内嵌的 Lucide 线框 SVG，无需请求第三方图标服务；许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
- 开启随机时确定剩余歌曲的顺序，之后的下一首、上一首、搜索和刷新都不会重洗它。播完一轮后开始新的一轮，并避免与上一轮末尾立即重复。
- 上一首沿实际播放历史后退，再按下一首会回到刚才离开的歌曲；这段前进历史也会在刷新后保留。
- 手动指定“下一首播放”的歌曲优先于历史前进、顺序与随机队列；直接点歌则保留剩余随机歌曲的相对顺序。
- 自绘进度条可拖动，也可聚焦后用键盘方向键调整。播放和暂停由实际音频事件同步到图标；唱片在播放时旋转，暂停、缓冲或出错时停止，并遵循系统的减少动态效果设置。

队列行为参考 [Spotify 对保留随机顺序的官方说明](https://community.spotify.com/forum/en/discussion/comment/7062728) 与 [Apple Music 的待播队列](https://support.apple.com/en-ie/109336)。

## 歌词目录

```text
Music/
├── 歌曲名 - 歌手.mp3
├── 另一首歌.mp3
└── Lyrics/
    ├── 歌曲名 - 歌手.lrc
    └── 另一首歌.lrc
```

优先选择完全同名的 `.lrc`；其次尝试不区分大小写的同名匹配，再尝试唯一的同前缀匹配，例如 `另一首歌翻译版.lrc`。多个前缀候选存在时不猜测。音频名重复带 `.mp3` 后缀时，也会尝试移除重复后缀来匹配歌词。

示例 LRC：

```lrc
[00:00.00]前奏
[00:05.20]第一行测试歌词
[00:10.50]第二行测试歌词
[00:10.50]同一时间戳的翻译
```

支持 UTF-8、UTF-8 BOM 和 GB18030 编码，支持多时间标签、同时间翻译与 `[offset:毫秒]`。无时间轴的文本静态显示；没有歌词时仍可播放音频。

歌词区仍可使用滚轮、触摸和键盘滚动。自动跟随使用 `requestAnimationFrame` 驱动的 420ms 三次缓入缓出，不依赖浏览器的平滑滚动。手动操作会立即取消动画，停止操作约 3 秒后再回到当前句；手动滚动不使用额外的缓动或阻尼。系统开启减少动态效果时直接定位。

## 刷新与状态恢复

播放状态保存在浏览器的 `localStorage` 中。同一浏览器、同一协议/域名/端口下刷新页面，会恢复歌曲选择、进度、随机顺序、前进历史、下一首待播队列和界面状态；恢复后保持暂停，点击播放继续。

这项功能保存的是播放记录，不会下载整个音乐库供离线播放。清除网站数据后记录会消失。不同浏览器之间不共享记录；同时打开多个标签页时，最后保存的记录生效。音乐根目录发生变化时会清除旧目录的歌曲选择，避免选中另一首同名文件。

## systemd 部署

仓库提供了 [`deploy/music-player.service`](deploy/music-player.service)。先修改其中的 `User`、`WorkingDirectory`、`ExecStart`，使其符合你的用户名、项目位置和音乐目录。用 `command -v python3` 确认 Python 的绝对路径。

```bash
sudo cp deploy/music-player.service /etc/systemd/system/music-player.service
sudo systemctl daemon-reload
sudo systemctl enable --now music-player.service
sudo systemctl status music-player.service
```

查看实时日志、重启或停止：

```bash
sudo journalctl -u music-player.service -f
sudo systemctl restart music-player.service
sudo systemctl stop music-player.service
```

修改 `.service` 文件后，需要再次执行 `daemon-reload`，再重启服务。

服务默认提供 HTTP。需要 HTTPS 时，可由已有转发入口或反向代理处理 TLS；使用 Nginx 时可将本服务绑定到 `127.0.0.1`，再代理对应端口。

## 更新

以克隆仓库的普通用户运行：

```bash
./update.sh
```

脚本会自动进入自身所在的项目目录，执行 `git pull --ff-only`，成功后通过 `sudo systemctl restart music-player.service` 重启服务。拉取失败时立即退出，不会重启服务；如需授权，`sudo` 会提示输入密码。

首次获取脚本可先执行 `git pull --ff-only`。脚本默认更新当前分支配置的上游，请在部署分支上运行；运行环境需要 Bash、Git、sudo 和已安装的 `music-player.service`。

## 测试

在项目根目录执行 HTTP 集成测试：

```bash
python3 -m unittest discover -v
```

测试使用临时音乐、歌词目录和本机回环地址，覆盖音频分段读取、歌词匹配与编码、HEAD 和目录访问限制。测试文件中的音频字节是传输测试数据。

可选：安装 Node.js 后运行前端逻辑测试，不需要 npm 安装：

```bash
node test_ui.cjs
```

覆盖随机播放、历史返回、待播队列优先级与取消、刷新恢复、搜索、存储不可用、旧请求竞争和歌词同步。音频解码和浏览器界面还应在目标浏览器中试播确认。

## 使用范围

这是一个供个人或少量用户使用的文件播放器，服务不带账号认证；能访问服务端口的用户可以播放、下载所选目录中的 MP3。它不提供上传、删除或音频转码。手机浏览器的连续后台播放取决于系统与浏览器行为。
